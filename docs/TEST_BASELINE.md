# 固定视频水印测试基线

本文件只记录可公开的测试元数据。私人素材、原始文件路径和抽帧图不进入仓库。

## 样本 P001

状态：已完成技术预检、固定区域定位、三条矩形基线和首条固定形状蒙版基线。

### 来源与公开边界

- 类型：用户提供的私人评估样本。
- 使用范围：本地研发测试。
- 再分发授权：未确认，因此视频、抽帧和音频不得提交到公开仓库。
- 无水印原片：当前未提供，因此不能用于 PSNR、SSIM 等有真值客观指标。

### 输入参数

| 项目 | 值 |
|---|---|
| 容器 | MP4 |
| 视频编码 | H.265 / HEVC Main |
| 分辨率 | 1470 × 630 |
| 像素格式 | yuv420p |
| 帧率 | 24 fps |
| 视频帧数 | 241 |
| 视频流时长 | 10.041667 秒 |
| 容器时长 | 10.080000 秒 |
| 音频 | AAC-LC，44.1 kHz，双声道 |
| 文件大小 | 1,539,974 字节 |

### 固定水印区域

- 水印类型：右下角不透明浅色文字标记。
- 三帧检查时间：0.5 秒、5.0 秒、9.5 秒。
- 初始矩形蒙版：`x=1318, y=570, width=144, height=50`。
- 坐标原点：画面左上角，单位为像素。
- 归一化区域：`x=0.8966, y=0.9048, width=0.0980, height=0.0794`。
- 结论：抽查位置一致，可作为固定矩形蒙版的首个私人输入样本。

### 评价限制

P001 的水印区域会经过暗色天空、人物、火光和雪地等不同背景。它适合观察残边、模糊块和跨帧闪烁，但由于没有无水印原片，只能做主观质量与技术完整性评价，不能证明恢复了原始像素。

### 基线 B001：FFmpeg `delogo`

| 项目 | 结果 |
|---|---|
| FFmpeg | 8.1.2 essentials build |
| 滤镜 | `delogo=x=1318:y=570:w=144:h=50:show=0` |
| 视频输出 | H.264 High，CRF 18，fast，yuv420p |
| 音频输出 | AAC码流直接复制；输入输出音频SHA-256一致 |
| 输出尺寸 / 帧率 / 帧数 | 1470 × 630 / 24 fps / 241帧 |
| 输出时长 | 视频10.041667秒；容器10.080000秒 |
| 处理耗时 | 0.773秒，约12.9倍实时速度 |
| 峰值内存 | 487,496 KiB，约476 MiB |
| GPU | 未启用；此基线为CPU处理 |
| 输出大小 | 4,033,581字节 |
| 质量等级 | C级，需要返修 |

抽查0.5秒、5.0秒和9.5秒后，水印文字本身已不可见，但整个蒙版区域形成明显的色带和涂抹矩形。简单暗背景也能辨认边界，人物、火光和雪地等复杂背景更明显；因此B001只通过技术完整性和速度基线，不通过产品画质要求。

### 基线 B002 / B003：OpenCV单帧补全

共同参数：OpenCV 4.14.0，固定矩形蒙版，修复半径3像素；输出H.264 High、CRF 18、fast、yuv420p，原AAC音频码流直接复制。

| 项目 | B002 Telea | B003 Navier–Stokes |
|---|---:|---:|
| 处理耗时 | 1.789665秒 | 1.945501秒 |
| 处理速度 | 134.662 fps | 123.876 fps |
| 实时倍速 | 5.611倍 | 5.161倍 |
| 峰值组合内存 | 491,831,296字节，约469 MiB | 491,466,752字节，约469 MiB |
| 输出大小 | 4,144,760字节 | 4,137,124字节 |
| 输出完整性 | 1470×630、24fps、241帧、10.08秒；音频哈希一致 | 同左 |
| GPU | 未启用 | 未启用 |
| 质量等级 | C级，需要返修 | C级，需要返修 |

三处相同时间点抽查显示：两种方法都能清除文字，矩形色带比B001略柔和，但整个区域仍有明显模糊和结构中断。Telea稍快；Navier–Stokes在此样本上没有可见质量优势。两者逐帧独立处理，不具备时间一致性约束，不能作为产品最终引擎。

### 当前阶段结论

前三条基线共同证明，直接删除整个`144×50`矩形会损失过多原画面。继续更换同类插值算法的收益有限；在引入更重模型前，应先把矩形蒙版收紧为覆盖文字和阴影的形状蒙版，再用相同输入复测。

### 基线 B004：固定亮色形状蒙版＋Telea

蒙版从完整241帧中提取持续偏亮、低饱和且位置固定的像素，再闭合并向外膨胀2像素。蒙版文件属于私人素材的衍生数据，不提交仓库。

| 项目 | 结果 |
|---|---|
| 原搜索矩形 | 7,200像素 |
| 形状蒙版 | 2,173像素，占原矩形30.1806% |
| 蒙版有效边界 | `x=1331, y=580, width=115, height=27` |
| 修复方法 | OpenCV Telea，半径3像素 |
| 处理耗时 | 1.452069秒 |
| 处理速度 | 165.970 fps，约6.915倍实时速度 |
| 峰值组合内存 | 493,621,248字节，约471 MiB |
| 输出大小 | 4,146,950字节 |
| 输出完整性 | 1470×630、24fps、241帧、10.08秒；音频哈希一致 |
| GPU | 未启用 |
| 静态抽帧等级 | B级候选 |
| 动态播放等级 | B级：仍能看见少量痕迹、有轻微闪烁，但基本可接受 |

与B002矩形Telea相比，B004少删除约69.82%的有效像素。0.5秒、5.0秒和9.5秒抽帧中的矩形边界基本消失，背景保留明显改善。正常速度人工复核确认仍能看到少量痕迹并有轻微闪烁，但整体基本可接受，因此最终记为B级，不记为A级。

### 水印区域外的重编码画质

B004/B005将原H.265视频解码后编码为H.264 CRF 18，因此技术上属于有损重编码。对不包含水印搜索矩形的两个主要区域进行逐帧FFmpeg PSNR/SSIM比较：

| 区域 | 画面占比 | PSNR | SSIM |
|---|---:|---:|---:|
| 左侧完整区域 | 约89.66% | 43.9044 dB | 0.991400 |
| 右上区域 | 约9.36% | 44.7040 dB | 0.993055 |

两部分合计覆盖约99.02%的画面。结论：水印外存在轻微压缩损失，但指标处于高保真范围；明显变化主要来自水印区域的主动补全。输出文件约4.15MB，大于1.54MB原文件，这是编码器和码率选择造成的，不能解释为无损或画质提升。

### 基线 B005：扩大1像素的形状蒙版

根据B004正常播放仍有少量残留的反馈，将形状蒙版膨胀从2次增加到3次，其余参数保持不变。

| 项目 | 结果 |
|---|---|
| 形状蒙版 | 2,548像素，占原矩形35.3889% |
| 蒙版有效边界 | `x=1330, y=579, width=117, height=29` |
| 处理耗时 | 1.607234秒 |
| 处理速度 | 149.947 fps，约6.248倍实时速度 |
| 峰值组合内存 | 493,559,808字节，约471 MiB |
| 输出大小 | 4,147,115字节 |
| 输出完整性 | 1470×630、24fps、241帧、10.08秒；音频哈希一致 |
| 静态抽帧等级 | B级候选；未重新出现矩形块 |
| 动态播放等级 | 待正常速度确认 |

B005比B004多处理375个边缘像素，目标是消除可见残边；它仍是逐帧补全，是否降低闪烁必须由正常速度播放确认。

### 基线 B006：H.265高保真输出

B006使用与B005相同的形状蒙版和Telea修复，只把视频输出从H.264 CRF 18 fast改为H.265 CRF 12 medium，并设置`hvc1`标签。目的是降低水印外的二次压缩损失，不改变修复算法。

| 项目 | B005兼容模式 | B006高保真模式 |
|---|---:|---:|
| 视频编码 | H.264 CRF 18 fast | H.265 CRF 12 medium |
| 处理耗时 | 1.607234秒 | 3.623668秒 |
| 实时倍速 | 6.248倍 | 2.771倍 |
| 峰值组合内存 | 约471 MiB | 775,688,192字节，约740 MiB |
| 输出大小 | 4,147,115字节 | 6,785,004字节 |
| 左侧区域PSNR / SSIM | 43.9044 dB / 0.991400 | 44.7816 dB / 0.995196 |
| 右上区域PSNR / SSIM | 44.7040 dB / 0.993055 | 45.1535 dB / 0.995745 |
| 音频 | AAC码流哈希一致 | AAC码流哈希一致 |

B006在两个水印外区域均提高了PSNR和SSIM，确认高保真设置确实减少了重编码损失。代价是耗时约2.25倍、文件约1.64倍、内存增加约269 MiB。对本项目10—15秒短视频和当前验证机器，这个成本可接受，因此原片为H.265时将B006作为当前推荐输出设置；它仍不能标记为数学无损。

### 后续实验要求

1. 所有算法必须复用同一矩形蒙版和输入文件。
2. 输出不得覆盖原文件，音频默认直通。
3. B001至B006已经完成；下一步正常速度确认B006的残留和闪烁。如果仍闪烁，再进入时间一致性修复。
4. 每次记录耗时、峰值内存、峰值显存、输出参数和 A/B/C/D 结果等级。
5. 仍需补充拥有无水印原片的合成水印样本，用于客观对照。
